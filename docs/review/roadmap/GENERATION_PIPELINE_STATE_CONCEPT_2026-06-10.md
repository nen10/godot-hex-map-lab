# Generation Pipeline State Concept 2026-06-10

Task: `GENPIPE-80_GENERATION_PIPELINE_STATE_CONCEPT`

## Summary

Do not build a generation node graph UI yet.

The current editor already has a useful immediate flow:

```text
Generation Profile / Generate controls
  -> transient Generate Preview
  -> QA candidate rows
  -> Apply / Promote
  -> final Level Document
```

The missing model is a persisted intermediate result boundary. Future work should introduce a `GenerationResultResource` or equivalent typed artifact before any graph UI. That result resource can hold primary, overlay, filter, and candidate map data with replay/provenance metadata. The final `HexMapDocumentResource` should stay the committed authoring resource and should not become a storage bucket for every intermediate pass.

## Current Implementation Evidence

| Area | Current representation | Concept implication |
|---|---|---|
| Generation Profile | `HexGenerationProfileResource` stores `profile_id`, `display_name`, `generator_id`, `default_seed`, `parameters`, and `metadata`. | Profile is input configuration. It does not own generated cells. |
| Generate Preview | `HexMapGenDock._current_data`, `_current_overlay_data`, `_last_generation_snapshot`, validation summary. | Preview is transient editor state, useful for display and apply, not a project asset. |
| Primary map output | `_generate_data_from_snapshot()` returns map data assigned to `_current_data` for normal generation. | Primary output is terrain/cell state until committed. |
| Overlay output | Overlay mode generates or merges `HexOverlayData` into `_current_overlay_data`. | Overlay output is a separate intermediate role, not terrain. |
| Filter / mask / reference data | `_create_generation_snapshot()` records `overlay_candidate_cells`, deductor floor cells, reference cells, adjacency rules, and query-row settings. | Filter data already exists conceptually but is currently control/snapshot state. |
| Candidate results | `run_generation_batch()` and `_batch_result_row()` store transient seed rows in `_last_batch_generation_results`. | QA candidates are summaries unless a future result resource persists them. |
| Document snapshot | `_generated_document_snapshot_for_data(primary_data, overlay_data)` converts current data into a `HexMapDocumentResource`. | Conversion is the commit boundary from generation state into authoring state. |
| Promotion | `promote_generation_seed_to_document()` creates a document from one seed result and attaches generation metadata. | Promotion creates final authoring data, not an intermediate graph. |

## State Roles

| State / Resource | Owns | Does not own | Current / future |
|---|---|---|---|
| Generation Profile | User-authored inputs: generator id, seed defaults, parameter values, future query/input references. | Generated cells, QA rows, final terrain. | Current concrete resource exists, but parameters are still broad. |
| Generation Run Snapshot | Sanitized run-time inputs for one execution. | Durable authoring state. | Current dictionary generated by `_create_generation_snapshot()`. |
| Generation Preview | Last generated primary/overlay data visible in Generate and target preview. | Project persistence by default. | Current transient dock state. |
| Generation Candidate | One seed/result row with score, validation summary, and output summary. | Committed document state. | Current QA row dictionary; future may reference a result resource. |
| Generation Result | Persisted intermediate output and provenance. | Final authoring ownership. | Future Resource/API model. |
| Level Document | Final terrain, overlay, object, label, zones, metadata, dependencies, and concise provenance. | Full pass graph/cache/intermediate history. | Current committed authoring resource. |

## Map Data Roles

| Role | Meaning | Current handling | Future handling |
|---|---|---|---|
| Primary map | Terrain/cell/wall map produced by generation. | `_current_data`; converted to `HexMapResource` and terrain layer on document snapshot. | Stored as primary output in Generation Result; copied into Level Document only on apply/promote. |
| Overlay map | Item-to-cells data generated or stacked over a primary map. | `_current_overlay_data`; converted into overlay tile payloads on document snapshot. | Stored as one or more named overlay outputs; mapped to document overlay layers on commit. |
| Filter / mask map | Constraint set used by a pass, such as placement mask, deductor floor, reference cells, crop result, or adjacency reference. | Query-row output and snapshot arrays; some filters derive from source registry mapdata. | Stored as typed intermediate/reference maps when persistence or replay is needed. |
| Candidate map | One generated result in a seed/batch comparison. | QA row summary, optionally promoted immediately to a document. | Optional Generation Result per candidate; row can reference result id/path. |
| Final map/document | Authoring state consumed by Paint, Validate, Layers, QA promotion target, and Runtime Handoff. | `HexMapDocumentResource` with terrain/overlay/object/label data and metadata. | Remains final authoring state with concise generation provenance. |

## Candidate Model Comparison

| Option | Description | Strengths | Risks | Decision |
|---|---|---|---|---|
| Resource pass model | Define typed Resource artifacts for Generation Result and, later, pass inputs/outputs. Passes can be saved, tested, replayed, and referenced without a live dock. | Best fit for Resource/API cleanup; clear save/load; testable; supports future QA persistence and provenance. | Needs schema design before UI payoff; may feel abstract before a browser/editor exists. | Adopt as first future implementation direction. |
| Linear pipeline | Store an ordered pass list with primary -> filter -> overlay -> final result steps. | Simple mental model; fits current Generate overlay flow; easier to expose as advanced profile settings. | Weak for branching, reused filters, multiple candidates, cache invalidation, and graph-like dependencies. | Good stepping stone after result resource exists. |
| Node graph | Visual nodes/edges for terrain, region, overlay, filter, candidate, cache, and final document passes. | Most expressive for advanced procedural workflows. | Premature UI cost; unclear serialization/invalidation; would bloat Generate; risks confusing preview/result/document ownership. | Research only until Resource pass and linear replay contracts exist. |

## Recommended Staging

1. Define `GenerationResultResource` or equivalent result artifact.
2. Add replay/apply API that can operate from profile/result resources without a live dock.
3. Let QA Seed Lab optionally persist a selected or generated candidate as a result resource.
4. Add a simple linear result/pass list only after result save/load is stable.
5. Revisit graph UI only after pass resources, dependency invalidation, and cache semantics are explicit.

## Minimal Future Result Resource Shape

This is a concept, not an implementation requirement for `GENPIPE-80`.

```text
HexGenerationResultResource
  result_id
  display_name
  source_profile: HexGenerationProfileResource or sanitized profile snapshot
  run_snapshot
  seed
  primary_map: HexMapResource
  overlay_maps: Array[HexOverlayResource]
  filter_maps / reference_maps: typed intermediate entries
  validation_summary
  status: previewed | accepted | rejected | superseded | committed
  committed_document_ref / generation_result_id in document metadata
  created_at / updated_at
```

Rules:

- Profile owns inputs.
- Result owns generated/intermediate outputs.
- Level Document owns final authoring data.
- Document metadata may reference a result, but the document must remain usable when the result is missing.
